**Two more real, previously-undocumented bugs found and fixed** via this
live run (in addition to Phase 6/7's `maven-settings` and
`artifacthub.io`/coschedule findings):

1. **`{{ git_auth_secret }}` template substitution does not reach inside
   an inlined custom Task's `env.valueFrom.secretKeyRef.name`.** First
   full-credentials run: `build-and-push-image` succeeded (image really
   pushed), but `update-deployment-tag` failed at pod creation —
   `spec.containers[0].env[0].valueFrom.secretKeyRef.name: Invalid value:
   "{{ git_auth_secret }}"` (literally unsubstituted, rejected by
   Kubernetes' RFC 1123 name validation). Confirmed by grepping the
   resolved YAML: the **top-level** `workspaces: - name: basic-auth
   secret: secretName:` binding *was* correctly substituted to the real
   generated secret name, but the **same variable inside the inlined
   Task's env block** was not — i.e. PAC's substitution reaches known
   top-level PipelineRun fields but not arbitrary text inside an inlined
   custom Task. The guide's own §8 recipe uses exactly this
   (`env.valueFrom.secretKeyRef.name: "{{ git_auth_secret }}"`) and would
   hit the same failure. **Fix:** dropped the `env`/`secretKeyRef`
   entirely; the Task now reads the token directly from the file GitHub
   auth already provides in the (correctly-substituted) `basic-auth`
   workspace: `GITHUB_TOKEN=$(cat
   "$(workspaces.basic-auth.path)/git-provider-token")`. Verified the key
   exists via `kubectl describe secret <pac-gitauth-*>` (`.git-credentials`,
   `.gitconfig`, `git-provider-token` — matches the guide's assumed key
   name). This sidesteps the substitution bug entirely rather than working
   around it, since it depends on a binding mechanism proven to work.
2. **`yq` is not installable via `microdnf` on `ubi9/ubi-minimal`** — the
   guide's `microdnf install -y git yq` fails outright (`error: No package
   matches 'yq'`), which also means `git` silently never got installed
   either (`microdnf` resolves the whole transaction atomically). Checked
   the cluster's node architecture (`kubectl get nodes -o
   custom-columns=...ARCH`) → `amd64`. **Fix:** install `git` alone via
   `microdnf`, download the `mikefarah/yq` static binary directly
   (`curl -sL .../yq_linux_amd64 -o /usr/local/bin/yq && chmod +x`) instead
   of relying on a package that doesn't exist for this base image.
3. **Installing `curl` via `microdnf` on top of `curl-minimal` conflicts**
   — `ubi9/ubi-minimal` ships `curl-minimal` by default, which provides
   the same binary; explicitly installing `curl` errors with a depsolve
   conflict. **Fix:** removed `curl` from the install list — `curl-minimal`
   already provides everything the fix above needs.
