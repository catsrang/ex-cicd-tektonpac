## Phase 3 — Custom Task: `tekton_ci/task.yaml`

**Status:** file written and schema-validated against the cluster API (2026-10-03). **Never executed** — no pod has run this Task. Not committed.

### What was created
`tekton_ci/task.yaml` — `Task` `clone-build-memory` (`tekton.dev/v1`).

| Element | Implementation |
|---|---|
| Params | `repo_url`, `revision`, `jar_path` (default `target/demo-0.0.1-SNAPSHOT.jar`) |
| Workspaces | `build-mem` (clone + build), `output` (hand-off); the Task does not fix either volume type |
| `stepTemplate` | image `registry.access.redhat.com/ubi9/openjdk-17:latest`, `runAsUser: 0` for all steps |
| Step `clone` | `microdnf install git`; `git init` + `git fetch --depth 1 origin <revision>` + `git checkout FETCH_HEAD` into `build-mem` (works for a SHA or a branch name) |
| Step `build` | `mvn -B -Dmaven.repo.local=/tmp/m2 package` in `build-mem`; memory request = limit = `2Gi`; `MAVEN_OPTS=-Xmx768m` |
| Step `copy` | fails if the jar is missing; copies `<jar_path>` and `Dockerfile` to `output` at the same relative paths; `chmod -R a+rX`; lists the result |

### Deviations from the plan
- **One image instead of a separate pinned git image.** All steps use the UBI OpenJDK 17 image and `clone` installs git with `microdnf`, the same idiom as `.tekton/tasks/update-deployment-tag.yaml`. This removes the second image and, with a single `runAsUser`, the UID-mismatch problem. Cost: a package install on every run.
- **`jar_path` param added** (defaulted) so the hard-coded jar name lives in one overridable place rather than inside the script. The `Dockerfile` still hard-codes the same name.
- **No `goals` param**: the goal is fixed to `package`, as the spec now requires.

| `kubectl create --dry-run=server` of a sample TaskRun (memory `emptyDir` 2Gi + `emptyDir` output) | accepted |

## Gotchas confirmed in this topic
1. **`emptyDir` is per-pod** — a memory workspace cannot carry data between Tekton tasks; clone + build must be steps of one Task.
2. **tmpfs is charged to the step's memory limit** — bound the JVM heap and keep `~/.m2` off the workspace.
3. **Outside PAC, Hub tasks need a resolver** — `taskRef: {name: buildah}` only works under PAC's annotation-driven inlining; standalone it is `resolver: hub`.
4. **A runtime-only Dockerfile moves the failure** — a Maven goal short of `package`, or a Dockerfile that still expects sources, fails at `buildah`, one task after the cause.
5. **Provenance ordering** — `pr.yaml` (`package`) must be on `main` before the Dockerfile change is.
